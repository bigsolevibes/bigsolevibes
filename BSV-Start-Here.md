## Why this file exists

Sessions kept arriving "lost" — re-asking questions Big D had already answered, or worse, confidently repeating stale facts. The root cause wasn't a missing read — it was **too many overlapping context docs with no agreed pecking order**, and the doc at the top of the old read list (`BSV-Memory.md` in the repo) was *not* the freshest one. A different doc — generated nightly straight to Drive — had moved on without it. Read order matters more than read volume. This file fixes the order.

## Read in this order, every session

1. **This file** — orientation + precedence rules (below) — local, fast
2. **Latest `standup-YYYY-MM-DD.md` in Drive `Reports/` folder** — the chief brief. Generated by `chief-of-staff.js` at 9:30AM daily using Claude. Has explicit **BIG D — DO THIS TODAY** and **BIG C — DO THIS TODAY** sections. Most actionable doc in the stack. Surface both action lists in the stand-up.
3. **`BSV-Session-Context.md` in Drive `Handoff/` folder** — regenerated nightly (~4AM) by `update-handoff.js`, template-rendered, no LLM drift. **This is the freshest strategic snapshot. When it conflicts with the repo's `BSV-Memory.md`, trust this one.**
4. **`BSV-BigC-Audit-Log.md`** (repo root) — last 5–10 entries — local, fast

**Read on demand only — do NOT read every session:**
- `BSV-Handoff-YYYY-MM-DD.md` — only if session-context is missing or stale
- `eng-report-YYYY-MM-DD.md` — only if standup flags active agent failures
- `cost-report-YYYY-MM-DD.md` — only if standup flags a budget alert
- `BSV-Memory.md` — only when brand voice or strategic decisions are in question
- **Live pipeline state** via `mcp__bsv__*` tools — only when current slot/approval status is needed

## Precedence rule (the actual fix)

When two sources disagree about *current state* (revenue, follower counts, pending approvals, blockers, what's been decided this week):

**Drive `BSV-Session-Context.md` > live MCP state > Audit Log > repo `BSV-Memory.md`**

The repo memory file is the brand bible — it changes rarely and on purpose (Big D approves strategic changes). The Drive session-context is the operational pulse — it's regenerated nightly and reflects what actually happened yesterday. Treat them as two different documents with two different jobs. Don't average them. Don't assume they agree.

As of 2026-06-07: the repo `BSV-Memory.md` is stamped **v1.0** (last touched 2026-05-29); the Drive session-context carries an embedded `BSV-Memory.md v2.0` (updated 2026-06-06) with material the repo copy is missing — most notably the **"Two Properties"** framing (The Lounge vs. The Sole Report as distinct arms with distinct jobs), an updated five-chapter shelf breakdown, the Camillen 60 removal (44/100, below the 70-point minimum), and sharper revenue-status language. **This drift should get reconciled** — see Open Threads below.
